# 画像ファイル管理規約

管理画面から登録する画像は、用途とコンテンツ単位で分類して保存します。異なる用途の画像を `uploads/` 直下へ混在させません。

```text
uploads/
├── hero/{hero-id}/
├── works/{work-id}/
├── maps/{map-id}/
├── news/{news-id}/
├── services/{service-id}/
├── strength/
├── company/
└── legacy/
```

## 実装ルール

- 施工事例、地図、ニュース、サービスなど複数レコードを持つコンテンツは、`コンテンツ種別/コンテンツID` の二階層にする。
- 会社情報など単一レコードの画像は、用途別の一階層にまとめる。
- ファイル名には推測困難で衝突しないランダムIDを使用し、利用者の元ファイル名を公開パスに使わない。
- 保存先はサーバー側で決定し、フォームから渡されたディレクトリ名をそのまま信用しない。
- 構成変更時は画像ファイルとJSON・DB等の参照パスを同時に移行し、片方だけを変更しない。
- 実行環境が所有するアップロードを、デプロイ処理で削除・上書きしない。
- 未参照と判断した既存画像はすぐ削除せず、`legacy/` に退避してから別途確認する。

この規約は沖縄サイトだけでなく、RISE GATEが制作・保守するCMS付きサイトの標準とします。静的なデザイン素材は `assets/`、運用中に登録される画像は `uploads/` に分離します。
