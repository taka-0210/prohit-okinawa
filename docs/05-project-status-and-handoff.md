## 多言語化の検討案

### 基本方針

- 日本語ページを構造と設定の基準にする。
- 写真、表示順、公開状態、レイアウト、リンクなどの管理は日本語CMSだけで行う。
- 英語・繁体字中国語には、翻訳テキスト専用の管理画面を言語別に用意する。
- 翻訳画面は日本語原文と翻訳入力欄を並べ、見出し・本文・ボタン名などを流し込むだけの構成にする。
- 更新頻度が低い想定のため、現時点ではGoogle Cloud TranslationなどのAPI連携を必須にしない。
- 日本語原文をもとにAIアシスタントが英語・繁体字中国語の翻訳案と、対象地域に合う表現を提案する。
- AIアシスタントの提案を人が確認・修正し、確定した文章だけを各言語CMSへ保存する運用を第一候補とする。
- 「ネイティブ品質」を保証する案件では、公開前に対象言語のネイティブ校正を追加する。

### サービスページで必要な設計

- 翻訳を表示順の番号だけで結び付けない。
- 各サービスと各 `PHOTO & TEXT` ブロックに、並べ替えても変わらない固有IDを持たせる。
- 日本語側で並べ替えた場合は、同じ固有IDの翻訳も一緒に追従させる。
- 日本語側で削除する場合は、対応する英語・繁体字データの扱いを確認できるようにする。
- 多言語対応の試作は一度ABOUT USで実施したが、2026年8月6日に取り外して日本語のみへ戻している。
